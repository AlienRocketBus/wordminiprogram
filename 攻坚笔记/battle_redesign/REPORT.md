# 拼写大PK · 对战界面 2.0 重新设计 —— 报告

**一句话**：所有线上对战画面（主页、天梯、匹配、各种错误、登录、大厅、选玩法、等待、进房、A/B/C 三种对战、交卷、结算、好友）都按岛内 Spelling Bee 对战机器人的样子重新设计了，共 **73 个状态**，每个状态都有暗色（深空蓝）和亮色（云端白）两版，在 390×844、360×640、320×568 三种屏幕上截图并实测。

**实测结果（438 张截图：73 个状态 × 暗/亮 × 3 种尺寸）**：文字对比度 **0 段不达标**；点击区 **0 个小于 44px**；320/360/390 三档 **0 处横向溢出**；页面没有任何一直在跑的动画，孩子不操作时主线程最忙 **1.05%**（CPU 降速 4 倍）。

## 2. 主要设计决定（为什么这么定）

1. **一个外观管全部对战画面。** 顶栏永远是「左上返回 · 居中标题 · 右边计时或状态」，取代原来 5 种返回/关闭写法；所有颜色走主题 2.0 角色，亮色版的问题（审计里 1.05–2.89 的那些）从根上消失，不再靠补丁。
2. **对战回合照搬 Spelling Bee 的骨架**：VS 条（双方头像、名字、大分数、各自状态牌）→ 题卡 → 字母格 → 贴底大键盘（键高 52，字 24）。旧的输入框换成字母格，`#prIn` 留着当真值（测试要它），视觉上隐藏。中间空出来的地方用来把题卡和字母格垂直居中，矮屏自动收紧。
3. **对手状态挂在对手那一侧**（✍️ 正在拼 / ✅ 拼对了 / 💤 没动静），提示条（网络、对手掉线、B/C 等对方）放在 VS 条下面，**永远不盖住计时和分数**，右边带倒数小牌。
4. **B/C 的提示按 v1164 的“等两个人”写**：对手先对时说「你拼对还能拿 80 / 60 分」+ 剩余秒数；我先对时键盘停用、说「等 小红 拼完」。
5. **天梯匹配是一个画面三个阶段**（找对手 → 开房等人 → 开打），20 秒交接不换画面、秒数不归零；只每秒改一次文字，不重建页面、不抢焦点。
6. **每种错误一个画面**，同一个组件：插画、标题、一句原因、一个下一步、可折叠的「给老师看的信息」（`config` 默认展开，方便拍照给老师）。所有 `alert`/`confirm` 换成画面或底部弹层。
7. **结算以比分为主角**（44px，赢的一边金框），先说做得好的地方；扣分用中性灰，不用红；平局在总战绩里写出来；词卡可以点了再听，把 PK 拉回学习。
8. **主页两份合成一份**：天梯（宽卡）+ 公开房间 + 好友约战，用岛屿玩法卡的语言（3D 插画 + 底板文字）；账号相关的全部收进「⚙️ 账号」弹层，孩子一进来先看到的是玩。
9. **选玩法改成“先选后开”**：三步（怎么出题 / 玩法 / 谁能进）+ 贴底的「开房！」，误点不会直接开出一间房；规则收进「ⓘ」弹层，规则文字仍然只从 `HansenPkRoom.MODES` 来。
10. **玩法名字不改**（抢答赛 / 回合赛 / 同步赛）：名字是 `MODES` 里的真源，测试和老师都认识；只把一行说明写成孩子能懂的话。审计建议把 B 改名“慢慢拼”，没采纳。
11. **动效完全按老师红线**：等待时没有任何循环动画（旧的旋转沙漏、摇摆放大镜都去掉），最后 5 秒是一次性变红而不是每秒放大；拼错不抖、输了不晃（审计建议的 wobble 没采纳）；庆祝只在结算播一次、播完清空。
12. **文案顺着测试和看门狗走**：所有等待画面的标题都是「等对手进来」，交卷后写「正在等对手交卷…」，对战里有「正在拼」——这样 `hansen_pk_watchdog_v1155.js` 仍能认出等待画面；「🔥 你抢先拼对！」「对手掉线了…」「🏆 对手已离场，本局你胜」「(你)」「➕ 开一间」「从云端恢复进度」「长按」「〔」等被测试 grep 的字样都保留了。

## 3. 测量结果

### 3.1 文字对比度（逐像素实测）

方法同主题 2.0 报告：每个画面截两张图，一张正常，一张把文字和 emoji 都藏起来；用文字下面真实像素的中位数当背景，按 WCAG 公式算。大字 = ≥24px，或 ≥18.66px 且加粗。390×844 和 360×640 两档都测（320 档只测溢出）。

| 主题 | 测了多少段文字 | 正文最低 | 大字最低 | 不达标 |
|---|---:|---:|---:|---:|
| 暗色 · 深空蓝 | 2824 | 4.7 | 8.43 | 0 |
| 亮色 · 云端白 | 2824 | 4.7 | 7.4 | 0 |

最低的 4.70 是红色角标上的白字（2.0 token `--badge-bg/--on-badge`，标准 4.5）。审计里的问题点现在的值：亮色输入的字母（旧 1.05）→ 字母格字 `--ink-1` 对 `--surface-2`；亮色房间卡（旧 1.22/1.94）、私密房码（旧 1.99）、“我”这一行（旧 1.86）、选中的出题卡（旧 1.12）、网络提示（旧 2.89）——全部在上表里，都 ≥4.5。

### 3.2 非文字（边框、图标、进度）

按 tokens.css 计算 20 对，暗/亮两套全部达标（`metrics/summary.md` 前两张表）。测量中发现并已修好 3 处：亮色下金色计时边（1.35）、金色“选中”框（1.69）、绿色进度条（2.70）→ 亮色改用 `--focus` / `--good`（SPEC §1 的 `--b-edge/--b-sel/--b-fill`）。

### 3.3 点击区与宽度

- 所有按钮、链接、输入框 ≥44×44（样稿按 48 做）；在线/隐身开关从 42 加高到 44。
- 字母键高 52（矮屏 48），最窄 27.8px @320、30.7px @360、33.7px @390——满足现有 `test_tap_targets_v1120` 的 ≥27px。10 列的键盘宽度做不到 44，所有手机键盘都一样，这是唯一的例外。
- 320 / 360 / 390：`scrollWidth == 视口宽度`，没有元素伸出屏幕；长名字（“王小红同学的超长名字”“甜甜同学今天也要赢”）都是省略号。
- 字体：CartoonBlack 和 Baloo2 用的是仓库根目录里打包的真文件，所有截图里用到的字体都加载成功；图片 0 个 404。

### 3.4 待机动画与耗电

- 146 个页面（73 状态 × 2 主题）加载 2.5 秒后：**运行中的动画 0 个**、样式表里 `infinite` 规则 **0** 条、rAF **0** 次/秒、残留特效层 0 个。每屏最多 1 个每秒一次的计时器（只改数字文字）。
- CPU 降速 4 倍、静置 8 秒的主线程忙碌：平均 **0.33%**，最高 **1.05%**（找对手，每秒改数字和进度环）。对照：主题 2.0 报告里现在的首页约 63%、岛屿菜单约 35%。
- 庆祝（赢的彩纸、拼对的星点）只在事件发生时播一次，结束后 `getAnimations()` 回到 0；`prefers-reduced-motion` 时直接显示终态（截图就是在这个模式下拍的）。

### 3.5 截图与对比图

- `shots/390x844/`、`shots/360x640/`（DPR 2）、`shots/320x568/`（DPR 1），文件名 `<状态>_<cosmos|cloud>.png`，共 438 张。
- `sheets/before_after_*.png`：天梯主页、找对手、公开房间、选玩法、等对手、对战（暗/亮）、结算赢、结算输（亮）、好友，共 10 张；左边是 v1163 体检截图。
- `sheets/reference_spellbee_vs_battle.png`：和 Spelling Bee 并排。
- `sheets/all_*.png`：13 组 × 暗/亮 × 390/360 的总览，共 52 张。

## 4. 没做 / 有意不做的

- **没改任何现有程序文件。** 本分支的对战代码是 v1163 的旧版，实现要在 v1164 的代码上按 `SPEC.md §8` 一步步来。
- 样稿里的数据（名字、分数、房间）是假的；倒数时长（2 分钟、45 秒、20 秒、8 秒“房主有点慢”）按任务说明和 v1163 代码写的，v1164 若不同以 v1164 为准。
- 声音（按键音、拼对“叮”、读单词）只写在规格里，样稿不出声。
- 头像用了游戏里 `avatars/` 的真图；实现时用 `hansen_avatar.js` 取玩家自己选的头像，对手头像要 v1164 的房间文档里带上头像编号（见待定问题 2）。
