# 拼写大PK · 对战界面 2.0 设计规格（SPEC）

> 给接手写代码的人看。样稿在 `mockups/`（`screen.html?s=<状态>&theme=cosmos|cloud`，目录页 `mockups/index.html`），截图在 `shots/`，量出来的数据在 `metrics/`，测试选择器清单在 `DOM_INVENTORY.md`。
> 本规格**只改外观和文案，不改对战逻辑**。逻辑以 v1164 分支为准（各写各的文档、房主 ACK 握手、错误分种类、天梯 20 秒后自己开房、B/C 等两个人）。

---

## 0. 一句话原则

1. **所有对战画面长得像岛内的 Spelling Bee 对战机器人**：顶栏（左返回 · 中标题 · 右计时）、VS 条带头像、题卡、字母格、贴底的大键盘、金色主按钮、卡通字标题。
2. **颜色只用 主题 2.0 的角色变量**（`攻坚笔记/next_inputs/theme_mockups/tokens.css`）。对战模块里不再出现十六进制颜色，亮色/暗色/12 套主题自动跟着走。
3. **一屏只有一个金色主按钮**；次要动作用靛蓝按钮或文字按钮。
4. **每种情况一个画面**：断网、慢、云端没连上、过期、配置、房间没了、被抢、同一个账号……各有各的插画、标题、一句原因、一个下一步。不再用 `alert`/`confirm`。
5. **老师的动效红线**：不闪屏、不震屏、不旋转、不一闪一闪、切屏不淡入、不挡做题。等待时没有任何循环动画，只有“每秒改一次数字”。

## 1. 颜色：别名层（`--b-*` 与旧变量）

样稿里的写法（`mockups/battle.css` 顶部）：

| 用途 | 2.0 角色 |
|---|---|
| 页面背景 | `--bg-1/2/3` + `--neb-1..3`（common.css 的 `body::after` 固定层） |
| 卡片 / 抬高面板 / 凹槽 | `--surface-1` / `--surface-2` / `--surface-3` |
| 主文字 / 次要 / 说明 | `--ink-1` / `--ink-2` / `--ink-3`（说明文字在样稿里一律用 `--ink-2`，更稳） |
| 数字、关键词 | `--hi` |
| 金色主按钮 | `--accent-1→--accent-2`，字 `--on-accent` |
| 靛蓝次按钮 | `--brand-1→--brand-2`，字 `--on-brand` |
| 对 / 错 | `--good`、`--good-surface`/`--on-good-surface`；`--bad`、`--bad-surface`/`--on-bad-surface` |
| 线 / 输入框边 / 焦点 | `--line`、`--line-strong`、`--focus` |
| 功能卡渐变 | `--f-*-a/b`；字一律压在 `--plate` 底板上（`--on-plate`） |
| 我 / 对手 | `--b-me = --accent-1`（金描边），`--b-opp = --f-blue-a`（暗）/ `--f-blue-b`（亮） |
| 键盘 | 托盘 `--surface-3`，键 `--surface-1`，字 `--ink-1`，删除键 `--brand-2` |

**和现有测试的冲突（必须处理）：** `test_theme_v1110.mjs` 要求 `--pk-*`（房间）和 `--hpk-*`（天梯、好友）定义在 `html:root` / `html.hsn-pal-light` 上、**变量定义里不能有 `var()`**、≥12 个变量。两条路：

- **A（推荐，2.0 主题落地后）**：把 `--pk-*`/`--hpk-*` 改成 2.0 角色的别名（`--pk-card:var(--surface-1)`），同时把 `test_theme_v1110` 的“不许 var()”改成“只许引用 2.0 角色名”。
- **B（2.0 还没落地时的过渡）**：脚本从 `tokens.css` 生成 `--pk-*`/`--hpk-*` 的**字面值**（cosmos → `html:root`，cloud → `html.hsn-pal-light`），测试不用改。等 2.0 落地再走 A。

无论哪条路，模块里的规则只写 `var(--pk-*)`/`var(--hpk-*)`，不写十六进制（`guard_theme_fg_follows_bg` 继续有效）。

## 4. 文案（定稿，照抄）

写法规则：一句话说发生了什么，一句话说下一步；不用“判负”“散了吧”“技术信息”“字符/分”“范围放宽”这类词；不用“他/她”指代对手时优先用名字（样稿里用“她”的两处是示例名字“小红”，实现时用名字或“对手”）；数字用 Baloo2。

### 4.3 错误与阻塞画面（按 v1164 的错误种类）

| kind | 插画 | 标题 | 原因 | 主按钮 | 文字按钮 | 其它 |

| network | brain_alarm | 连不上网络 | 对战要联网才能找到对手。连上 Wi-Fi 或打开流量，再点一下。 | 再试一次（天梯里可保留旧文案「重新找对手」，测试正则二选一即可） | 先不玩了 | 「正在自动重试…」；`navigator.onLine===false` 或第一次失败就显示 |

## 7. 无障碍与尺寸

- **对比度**：正文 ≥4.5，大字（≥24px 或 ≥18.66px 粗）≥3，图标与边框 ≥3。实测见 `REPORT.md` 和 `metrics/measure.json`。
- **点击区**：所有按钮、链接、输入框 ≥44×44（样稿用 48）。字母键高 52（矮屏 48），宽 = (屏宽 − 间距)/10，320 宽时 27.6px —— 和所有手机键盘一样，宽度做不到 44，满足现有 `test_tap_targets_v1120` 的 ≥27。
- **不横向溢出**：320 / 360 / 390 三档实测为 0。长名字一律省略号（VS 条、房间卡、好友行、座位）。
- **读屏**：顶栏返回有文字；✕ 有 `aria-label`；选择卡是 `role=radio` + `aria-checked`；计时 `role=timer`；揭晓 `role=status`；错误 `role=alert`；秒数计数器 `aria-live="off"`（每秒播报太吵），阶段变化时才用 `aria-live="polite"` 报一次「已经帮你开好房」。
- **焦点**：进画面时焦点放标题或主按钮一次；之后的每秒更新不动焦点。
- **字体**：标题/按钮 CartoonBlack，数字和英文 Baloo2（`baloo2.woff2` 已打包），正文系统字。`font-display:block` 避免数字跳宽；`font-variant-numeric:tabular-nums`。
- **emoji**：图标位优先用 3D 插画（`icons/*.webp`、`ui/brain_*.webp`）和 2.0 的 SVG 图标；emoji 只出现在文字里，缺字时也不影响理解。
