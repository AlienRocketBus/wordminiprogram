## 2.2 已确凿查明的机制（读 SDK 源码 + 用户日志，不是推测）

### ① 一次被拒的请求会毁掉整个登录会话

```js
// vendor_cloudbase_esm_v965.js 请求拦截器
if (withCredentials && resp.error === UNAUTHENTICATED)
    setCredentials(null)          // ← 把整个凭证删掉
```

### ② 手机号会话刷新失败没有兜底

```js
if (刷新失败) {
  if (scope === "anonymous") → anonymousLogin() 兜底 ✅
  else                        → reject → 凭证被删 ❌
}
```

**这也解释了为什么用户关掉匿名登录后问题更明显。**

### ③ 过期判据极宽松

```js
function qe(t){ var e = true;                    // ← 默认就算过期
  if (t?.expires_at && t?.access_token) e = (t.expires_at < new Date);
  return e; }
```

### ④ 用户日志给出的直接原因

```
HTTP 400 /auth/v1/token
invalid_grant | invalid refresh token. for it may be has been refreshed by
❗删除 credentials_ambitious-…  原有 1314 字节   ← SDK 自己删的
```

**「refresh token 已经被别人刷新过了」** —— 多实例并发刷新。

## 2.3 已做的四层防线

| 版本 | 做法 |
|---|---|
| v1088 | 云存档：已登录时不另建实例（判断必须在 `cloudbase.init` **之前**） |
| v1090 | 账号模块：子框内也不建实例 |
| v1091/v1093 | **修正过度拦截** —— 同源时借用顶层实例，`app()` 与 `auth()` 都要改 |
| v1092 | **凭证守护**：影子备份 + 跨页刷新锁 + 失败即救回 |

**实测：全站 CloudBase 实例数 = 1；凭证被删后 3 秒内自动救回。**

## 2.4 ⚠️ 仍未回答的问题

> **服务端最初为什么会回 `UNAUTHENTICATED`？**

可能性（**未验证，不要当结论**）：数据库权限规则 / 新账号服务端未就绪 /
用户当前把**匿名登录关掉了**（见 4.2）。

**下一步就靠诊断面板**：v1085/v1087 的「🪤 凭证生死簿」会写出
**是哪个请求、哪张表、什么错误码**触发了清除，且**跨页面重载存活**。

## 2.5 ⚠️ 不要采纳 PR #2 的建议

PR #2 主张注册流程改成 `getVerification → verify → signUp`。
**读 SDK 本体证实这是错的**：官方 `signUpWithPhoneCode` 就是直接
`signUp(原始短信码)`，先 `verify()` 会**消耗验证码**，使注册必然失败。
