# 单词大冒险 v1163 — 儿童隐私 / 安全 / 数据保护审查

对象：7–10 岁儿童英语词汇 H5（主要在微信内置浏览器打开）。只读审查 `scratchpad/v1163_snapshot`（VERSION 1163）。
证据脚本/输出：`scratchpad/allround/privacy-safety/`（lib.mjs、s01_external_requests.mjs → out/s01_external_requests.json、keyderiv.mjs、audio_cov_out.txt）。
法律结论标注「待确认」：未成年人保护 / 个人信息保护的具体条文需法务确认，这里只讲工程事实与风险。

> **背景（来自本仓库权威记录，非本次推测）**：`hansen_pk_rooms` 与 `hansen_saves` 控制台权限是「读取全部数据，修改本人数据」（交接_必读_给下一个对话.md:231、README.md:1870）——**任何已登录用户都能读到这两个集合里的每一条文档**，只能改自己的。`hansen_friends`、`hansen_friend_msgs` 是「所有用户可读，仅创建者可写」（CHANGELOG.md:3285-3286）。`counters` 为 ADMINONLY。这几条权限是下面多数问题的根。

## 一、给老师的大白话总结
这个程序**不联网也能完整玩**，单机学习部分很干净：没有广告、没有统计/追踪代码、没有加载任何外部字体或第三方脚本（实测打开任意页面都 0 对外请求）。隐私风险**全部集中在"要登录的那部分"**——账号、云存档、在线对战、排行榜、好友。孩子不注册、不打在线对战，基本无对外暴露。

登录之后按严重程度：
1. **（最严重，v1164 正在修）在线对战房间里直接存了孩子的手机号**，而房间列表是"所有登录的人都能看到全部"——等于把一批孩子的手机号摆在公开桌上。新版改成只用内部编号、不写手机号，这条就能解决；**务必确认新版真改掉了**。
2. **云存档的"解锁钥匙"是用手机号算出来的**，而云存档又"人人可读全部"。合起来：**谁知道一个孩子的手机号，就能把这孩子的整份存档（名字、编号、全部进度）解出来**。新版**还没动**，要单独处理。
3. **排行榜/好友/在线状态"人人可见全部"**：别人能看到所有孩子起的名字、编号（编号还顺着 1、2、3 排、能挨个数出来）、谁在线、谁和谁好友。
4. **起名字没拦真名和手机号**——孩子能把真名/手机号设成排行榜公开显示的名字。
5. **首页有隐私弹窗（好），但只讲了"本地存档"和"发音可能联网"**，没提账号要手机号、云存档、在线对战会公开名字编号；也没有"家长同意"和"删除账号/云端数据"的入口。

好的方面要保留：云存档真加密（AES-GCM）；显示别人数据的地方都做了转义（未发现 XSS）；聊天只能发 10 句固定话、不能自由打字（完全避开陌生人发任意内容）；仓库没藏密钥/令牌（环境 ID 是设计上就公开的，不算泄密）。

## 二、详细发现（按严重程度，含证据与修法）

### PS-01 · 严重 · 房间文档存手机号且全库可读（v1164 已在修，须确认）
事实：`me().id = String(lc.phone||lc.username||lc.uid)`（hansen_pk_room_v1065.js:467），开房 `hostId:u.id`（:592）、进房 `guestId:u.id`（:828）；`hansen_pk_rooms` 读取全部（交接_必读:231）。后果：任一登录用户读到所有在线房间的**明文手机号**。注：v1163 里 `me().name` 恒为「无名蜂」（无 status()），所以房间只暴露手机号作 id、无真名。修法：SPEC_v1164 §3 已规定 `u+uid` 且不写手机号——**确认**房间文档 hostId/guestId 为 `u<uid>`、me().id 不读 lc.phone、守卫到位（SPEC §8 'no phone/username in room docs'）。

### PS-02 · 严重 · 存档钥匙由手机号推导 + hansen_saves 全库可读（v1164 未覆盖）
事实：`accountIdent()`='p:'+手机号（hansen_cloud_save_v965.js:87-94）；`ensureKey→keyFromUid`（:139-168）确定性推密钥；`docIdOf/aesKeyOf=SHA-256(前缀+key)`（:201-206）；hansen_saves 读取全部。验证：`keyderiv.mjs`（用程序自身算法）证明手机号 13900000000 → 固定 docId `c5f24e19…` 与固定 AES 密钥，无任何秘密输入。后果：知道手机号即可解密整份存档（名字、cid、全部进度；手机号本身被 DENY 排除，hansen_backup_v944.js:30）。v1163 里手机号可从房间批量收割（PS-01）构成完整链；即便 v1164 从房间去手机号，"知手机号即可解档"结构性弱点仍在。文档地址 256 位不可枚举→定向风险而非一键脱库。代码注释（:72-76）自称隔离靠权限，但该集合是读取全部，前提不成立。修法（择一，待法务定）：①密钥改真随机、只存设备+水晶密钥，账号绑定用独立映射文档；②hansen_saves 收紧为仅创建者读写并用稳定 uid 作归属；③至少加 per-account 随机 salt（服务端下发、存账号文档）进 docId/aesKey，使其不可由手机号得出。

### PS-03 · 高 · 社交层全库可读（v1164 未覆盖）
事实：排行榜 `fetchTop` 读全表并回传 `uid(=x.uid||x._id)、name、cid、rating`（hansen_ladder_board_v1156.js:150-166，泄露 CloudBase uid）；好友页 `listFriends` 做 `T().list({kind:'presence'})` 整表拉取所有人 name/cid/at/_openid（hansen_friends_v1106.js:~335）；friends/friend_msgs 所有人可读（CHANGELOG:3285-3286）；cid 为注册顺序（hansen_auth_v1004.js:665）可枚举。后果：任一登录用户可读全体用户名字、竞赛 ID、在线状态、好友图、消息元数据（内容仅 10 条固定短语 id）。修法：排行榜改云函数返回脱敏 Top-N（去 uid/openid）；presence/好友按好友关系用自定义规则/云函数收紧；friend_msgs 仅收件人可读。SPEC §5 只提写自身/查 {code}，未涉读范围——须补（服务端规则可行性待确认）。

### PS-04 · 高 · 起名未拦真名/手机号且公开显示（v1164 未覆盖）
事实：`validateName` 仅 2–12 字、禁 `<>"'`\\/` 与控制字符+小禁词（hansen_sb_profile_v1002.js:126-137）；2 字真名、11 位手机号可过。该 name 公开在排行榜（PS-03）、资料页、（新版）房间 VS 条。`normUsername`（hansen_auth_v1004.js:491-497）同理（用户名不公开，风险较低）。修法：公开昵称禁 7+ 连续数字（疑似手机/QQ）、保留并扩充禁词、旁加家长提示。

### PS-05 · 中 · 隐私说明不完整、无家长同意（v1164 未覆盖）
事实：首页隐私弹窗（index.html:3800-3812）覆盖本地存档、发音可能请求百度/有道/Google、离线缓存、腾讯问卷；**未覆盖**账号收手机号/用户名、云存档上传全部进度、在线对战/排行榜/好友公开 name+cid+在线状态，也无家长/年龄告知。修法：补"账号与在线功能"段（手机号、云存档内容、哪些字段公开、腾讯云 CloudBase 承载），在**首次注册/首次在线对战前**给家长告知与确认。法律细节待确认。

### PS-06 · 中 · 无删除云端存档/注销账号/退出排行榜入口（v1164 未覆盖）
事实：全仓库无删除账号/云端数据路径；仅 `allowEmpty` 清空云端且无 UI（hansen_cloud_save_v965.js:600-605）。修法：提供"退出并删除云端存档"（删自己的 hansen_saves 文档）与"从排行榜隐藏/删除我的数据"（清 sb_profile 的 ladder/name）。支撑删除权（待确认）。

### PS-07 · 中 · 可向任意（可枚举）cid 发起联系，无屏蔽/举报，收件箱未接线
事实：`sendQuick(toCid,quickId)` 不校验好友关系（hansen_friends_v1106.js:393-408），任意数字 cid 可收固定短语；好友"请求"亦可发任意 cid；cid 可枚举（PS-03）；`inbox()` 有实现但无 UI 调用（hansen_friends_ui 无渲染）——孩子看不到也无法管理；无屏蔽/举报。修法：sendQuick 限互为好友；接入收件箱并加屏蔽/删除/举报；好友请求可拒绝。内容风险低（固定短语）但属陌生人联系且孩子无从管理。

### PS-08 · 低 · 发音兜底会把词/句文本+IP 发给百度/有道/Google
事实：本地音频覆盖全部 696 词+240 星海词+709 例句（audio_cov_out.txt，0 缺失），页面加载 0 对外请求（out/s01_external_requests.json）；但本地 mp3 失败时单词兜底依次请求 ssl.gstatic.com、fanyi.baidu.com（template.html:2609-2620，URL 含文本），设置页"试听"直连所选 provider（:7823-7829）。已在隐私弹窗披露。修法：本地已 100% 覆盖，可将在线 TTS 兜底默认关闭/家长可选开启，或只留浏览器本地合成兜底。

### PS-09 · 低 · 手机号明文入 localStorage（共享设备泄露）
事实：`writeLocal({...phone:st.pendingPhone...})`（hansen_auth_v1004.js:437），键 hansen_auth_v1004 明文含 +86 手机号；UI/诊断也显示（hansen_auth_ui_v1004.js:67、hansen_cloud_diag_v1027.js:109）。孩子常共用手机→下一个使用者/任意页面脚本可读到上一个孩子手机号（并经 PS-02 推出存档钥匙）。修法：本地只存 uid，不存明文手机号；显示时脱敏（138****0000）。

### PS-10 · 低 · 卡牌管理员口令 6 位数字、客户端校验、可从客户端还原（非 PII 控制项）
事实：`checkCardPw` 用 `SHA-256(pw)===CARD_SHA`（CARD_SHA 在客户端，hansen_boss_attack.js:14996），回退 `djb2(pw)===CARD_DJB && pw.length===6`（:15064-15076），10^6 空间可从客户端指纹离线还原；主门 50 位（:14985）不可枚举。任何客户端口令门亦可在开发者工具绕过。它只解锁"一键通关/卡册显示"作弊项，不保护任何个人信息。修法：当便利开关看待；若在意，卡牌口令改高熵或改设备级隐藏手势。低优先。

### PS-11 · 中 · `privacy` 资料字段是摆设：存了但从不生效、无设置入口
事实：`readProfile` 会读 privacy（hansen_sb_profile_v1002.js:37），但无任何可见性判断据此做，也无写入该字段的 UI/setter（只有默认 'public'，:27、:502）。后果：将来给家长"设私密"开关也不会隐藏任何东西，易造成"设了没用"的错觉。修法：实现它（排行榜/好友/presence 按 privacy 过滤 + 设置入口）或删掉该误导字段。与 PS-03 一并设计。

### PS-12 · 良好实践（保持，勿回退）
实测 8 个关键页登录/未登录态均 0 对外请求（out/s01_external_requests.json），字体本地 .woff2，无分析 SDK；云存档 AES-GCM 零知识信封设计正确（:201-223，问题只在钥匙来源 PS-02）；别人数据渲染处普遍 esc()/sText()/sNum()（hansen_pk_room_ui_v1065.js:374/:577、hansen_ladder_ui_v1108.js:537、hansen_friends_ui_v1107.js:338/:432、hansen_pk_room_v1065.js:712-735），未发现未转义远端数据注入点；消息只能发固定短语 id+不存文本+_openid 冒充校验（hansen_friends_v1106.js:393-456）；备份 DENY 排除凭证/hansen_auth_/cloud-state（hansen_backup_v944.js:30,85-94）；环境 ID 公开属 CloudBase 设计预期（cloudbaserc.json:3），app 代码中未发现 API key/令牌/私钥明文（管理员密码明文也不在代码里，仅指纹）。建议：加守卫固化转义、DENY 列表、固定短语约束，防未来重构削弱（SPEC §8 已有部分守卫，扩展到这几项）。
