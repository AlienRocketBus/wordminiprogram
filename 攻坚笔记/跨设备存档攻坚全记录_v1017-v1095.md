# 第一部分 · 结论先行：如果重来一次该怎么做

## 1.1 最贵的一条教训

> **看不见现场，就不要动手改代码。**

这条我违反了**四次**（v1076/v1077/v1079/v1080），每一次都：
提出假设 → 改代码 → 发版 → 等用户截图 → 发现猜错 → 再来一遍。

**每一轮消耗一天，四轮就是四天。**

而真正解决问题的转折点，是 v1078 做出「会话探测轨迹」、
v1085 做出「凭证生死簿」—— **这两个工具本该是第一步，我做到了第二十步。**

## 1.2 如果重来，正确的顺序

```
第 1 步：确认「用户跑的是不是我改的版本」
        ← 这一步不做，后面所有诊断都可能基于旧代码的现象

第 2 步：造一个能看见现场的工具
        ← 面板上显示：版本号 / 关键状态 / 完整时间线 / 调用栈

第 3 步：让用户截一张图

第 4 步：照着图上的事实改代码

第 5 步：改完把牵动的整条链走一遍再发版
```

**我实际的顺序是：4 → 4 → 4 → 4 →（终于）2 → 1 → 4 → 5。**

## 1.3 三条具体的操作准则

| 准则 | 来自哪次教训 |
|---|---|
| **先扫真实数据，再下结论** | v1095：我凭"最近改了什么"推断，真凶其实是中文键名 |
| **改动超过三处就整段重写** | `hansen_cred_trap` 被反复切割改坏三次 |
| **改完走整条调用链，不是只测改的那一处** | v1090/v1093/v1094 连续三次「修 A 弄坏 B」 |

# 第二部分 · 六个真凶的完整技术剖析

这个问题**不是一个 bug，是六个独立的 bug 叠在一起**。
每修掉一个，下一个才浮出水面 —— 这也是它拖这么久的客观原因。

---

## 真凶 ①：登录状态有两个真源（v1059）

### 现象
界面顶部写着「✅ 已登录 +86 186xxxxxxxx」，
同一页诊断面板却写着「❌ 云端会话已失效」，
每次云端读写返回 `{"error":"unauthenticated"}`。

### 根因

代码里有两个判断"是否登录"的函数：

```js
// 真源 A：真去问云端
function verifySession() { ... 调用 SDK 的 getLoginState() ... }

// 真源 B：只翻本地记录
function isSignedIn() {
  var lc = readLocal();
  return !!(lc.method && lc.signedAt);   // 「我登录过」≠「我还登录着」
}
```

**`verifySession()` 早在 v1031 就写好了，但从未被任何一处决定采用。**
而 `isSignedIn()` 被 **8 处**要做决定的地方使用。

于是会话过期后：面板正确显示"已失效"，`isSignedIn()` 照样返回 true，
界面继续显示已登录，云存档拿着**没有凭证的实例**去读数据库。

### 修复
```js
function ensureSession() {   // 云端读写的唯一通行证
  if (!isSignedIn()) return { ok:false, reason:'not-signed-in' };
  return auth().then(a => a.getLoginState()).then(st => {
    var uid = st && (st.uid || (st.user && st.user.uid));
    return uid ? { ok:true, uid } : { ok:false, ... };
  });
}
```
8 处决定点全部改走 `ensureSession()`。

### ⚠️ 这里有个更危险的坑（差点造成更大事故）

**空的 `getLoginState()` 不足以把用户登出**：
- SDK 恢复持久化会话是异步的，问得太早同样返回空
- 断网时某些版本也返回空而非抛错

据此登出，等于「进一次隧道 / 开机快一点」就把人踢出登录。

**规则**：空登录态只拦操作、不清标记；
只有云端**明确回 `unauthenticated`** 这类确凿鉴权错误，才清本地标记。

## 真凶 ②：`[object Object]` 盖住真错误，盖了 40 版（v1059）

### 根因

CloudBase 抛的是**普通对象**（无 `.message`、非 Error 实例），
而所有报错出口都是字符串拼接：

```js
msg = '同步失败：' + err;      // → "同步失败：[object Object]"
```

**v1017 到 v1058，每一版改的都是真 bug，但看不见错误原文，只能靠推理。**

诊断面板存在的意义就是把现场显示出来，**它自己却把最关键的一句吃掉了**。

### 修复
```js
function errText(e) {
  if (e == null) return '';
  if (typeof e === 'string') return e;
  var parts = [];
  for (var k of ['error_description','errMsg','message','error','code','reason'])
    if (e[k] != null && typeof e[k] !== 'object') parts.push(String(e[k]));
  if (parts.length) return parts.join(' | ');
  try { var j = JSON.stringify(e); if (j && j !== '{}') return j; } catch(_) {}
  return '(无法解析的错误对象)';
}
```
挂到 `window.HBErrText`，全仓统一使用。

### 教训

> **报错链路是唯一能看见现场的通道，不许在上面堆任何会撒谎的东西。**

这条我后来又违反了两次（见真凶 ③ 和 v1068）。

## 真凶 ③：准确文案被一条老规则改写（v1068）

### 现象
同一时刻、同一个错误，界面上出现**两种互相矛盾的说法**：
```
上传：云端匿名登录未开通（见开通指南第2步）    ← 走 friendly()
拉取：云端登录已过期，请重新登录后再同步        ← 不走 friendly()
```
而前者会把人引去开通一个**根本不相干**的配置。

### 根因
```js
if (/anonymous|ANONYMOUS|登录|auth/i.test(m))
    return '云端匿名登录未开通（见开通指南第2步）';
```

正则里含 **`登录`** 两字通配 —— 而 v1059 写的准确原文是
「云端**登录**已过期，请重新登录后再同步」，**被它整个吞掉改写了**。

### 修复
1. 自己产生的错误（带 `friendly` / `sessionDead` 标记）**原样透出**
2. 已是人话的文案直接透出
3. 匿名规则只认真正的特征词（`anonymous` / `signInAnonymously` / `匿名`）

## 真凶 ④：「做出来的东西不显示」（v1082~v1084）

### 这可能是前二十版全部白费的根本原因

用户一句话点破：
> 「你做出来的东西有可能根本就没显示出来，你做完了但可能还是上个版本。」

### 根因

```js
const NAVIGATION_TIMEOUT_MS = 3000;   // 有缓存时，网络超过 3 秒就退回旧缓存
```

Service Worker 对页面是"网络优先"，**但有缓存时只等 3 秒**。
用户在微信内置浏览器、信号一波动就超时 → 拿到缓存里的旧 HTML；
而 **HTML 文件名不带版本戳**（不像 JS 有 `?v=`），旧页面被一直复用，
里面引用的又全是旧版 JS。

**结果：开发端连改六版，用户手机上跑的仍是旧代码，而双方都看不出来。**

### 为什么"面板显示两个版本号"不够

我第一版的办法是在面板显示「模块版本 vs 页面版本」，指望不一致时能看出来。
**但那检测不出来** —— SW 给的是**整套**旧文件，两个数字会**一致地都是旧的**。

### 正确做法：去服务器问

```js
// 用 no-store + 时间戳，绕开一切缓存层
fetch(location.origin + '/VERSION?_vw=' + Date.now(), { cache:'no-store' })
  .then(r => r.text())
  .then(t => { if (Number(t) > 本机版本) 自动清缓存并硬重载; });
```

**唯一可靠的判据是去服务器问"最新是哪一版" —— 那是缓存管不着的地方。**

### v1084 又发现三处会让它彻底失效的缺陷

| 缺陷 | 后果 |
|---|---|
| **iframe 里 `location.replace` 只重载子框** | 外壳仍是旧版（外壳才注册 SW），**等于白修** |
| **相对路径 `'VERSION?…'`** | iframe/子路径下解析错 → 永远取不到 → **形同虚设** |
| **没有 XHR 兜底** | 老内核没 fetch → **在用户所在环境根本不运行** |

### 教训

> **任何诊断工具，第一行必须先说清「我是哪一版」。**
> 否则它给出的所有信息都可能对不上号。

## 真凶 ⑤：多个 CloudBase 实例并发刷新 refresh_token（v1088~v1093）

### 用户凭证生死簿抓到的现行

```
12:44:29  HTTP 400  /auth/v1/token?client_id=ambitious-…
          invalid_grant | invalid refresh token.
                          for it may be has been refreshed by

12:44:29  ❗删除  credentials_ambitious-…  原有 1314 字节
          t.<anonymous> (vendor_cloudbase_esm_v965.js)   ← SDK 自己删的
```

**「refresh token 无效 —— 因为它可能已经被别人刷新过了」**

### 完整链条（读 SDK 源码确认，不是推测）

```js
// ① 过期判据：缺 expires_at 或 access_token 就**默认算过期** → 立刻刷新
function qe(t){ var e = true;
  if (t?.expires_at && t?.access_token) e = (t.expires_at < new Date);
  return e; }

// ② 刷新失败后：
if (刷新失败) {
  if (scope === "anonymous") → anonymousLogin() 重新登录兜底 ✅
  else                        → reject → **凭证被删** ❌
}

// ③ 请求拦截器：
if (withCredentials && resp.error === UNAUTHENTICATED)
    setCredentials(null)      // ← 把整个凭证删掉
```

**手机号登录的会话，刷新一旦失败就没有任何兜底，直接完蛋。**
（匿名会话反而有兜底 —— 这也解释了为什么用户关掉匿名登录后问题更明显。）

### 谁在并发刷新

- 云存档模块自己 `cloudbase.init()` 建了一个实例
- 账号模块也建了一个
- **5 个预热 iframe**（land_map / island_season / boss_hall / season_showcase / spelling_bee）各自加载完整模块
- 多标签页 / 多次打开小程序

**每个实例有各自的内存态，却共用同一个 localStorage 凭证槽位。**
A 刷新成功写入新 token，B 手里还是旧的 → 下次刷新必然 `invalid_grant`。

### 修复四层

| 版本 | 做法 | 关键点 |
|---|---|---|
| v1088 | 云存档：已登录时复用账号实例 | **判断必须在 `cloudbase.init` 之前**（v1076 就错在放到了后面，晚了 900 字符） |
| v1090 | 账号模块：子框内也不建实例 | v1088 只堵了一半 |
| v1091/v1093 | **修正过度拦截**：同源时借用顶层实例 | 见下方"事故" |
| v1092 | 凭证守护：影子备份 + 跨页刷新锁 + 失败即救回 | SDK 内部改不了，在外面兜住 |

### 🔴 这里我造成了两次事故

**v1090 → 登录点不了**
为堵多实例，我加了「iframe 内**一律**不创建云端实例」。
**但拼写大PK 本身就在 iframe 壳里跑** —— 登录面板正在那个子框内。
用户看到：「登录没成功：子页面不创建云端实例」。

> **我把「后台自动刷新」和「用户主动登录」当成同一件事拦了。**
> 正确的界线：后台自动行为该拦，用户主动操作必须放行。

**v1093 → 报「鉴权不可用」**
v1091 让子框借用顶层实例，改的是 `app()`，**但 `auth()` 没跟着改**：
```js
function auth() {
  return app().then(function () {
    if (!_auth) throw new Error('鉴权不可用');   // ← _auth 在子框里永远是 null
    return _auth;
  });
}
```

> **同一个疏漏的两半，我只改了一半。**

## 真凶 ⑥：备份不认中文键名（v1095）— 最后一根稻草

### 现象
登录成功后点「立即把进度存到云端」，一直报：
```
备份含非法键或非字符串值
```

### 我先猜错了一次（v1094）

我以为是自己加的诊断键污染了备份：
```
hansen_credtrap_log / hansen_cred_shadow / hansen_vw_autofixed
```
它们都以 `hansen_` 开头，正好落进备份收录前缀。

**这个判断只对了一半** —— 诊断键确实该排除（v1094 修的是对的），
**但真正卡住用户的不是它。**

### 真凶（扫描用户真实 localStorage 找到）

```
hsn_progress:动物大冒险      ← 键名里有中文
hsn_progress:食物岛
```

这是 `hansen_mylearning.js` 写的「我的学习」跨岛聚合数据，
键名格式就是 `hsn_progress:<岛屿标题>` —— **而岛屿标题本来就是中文**。

而备份的键名校验是：
```js
/^[A-Za-z0-9_:\-.]+$/     // ← 只允许英文数字，中文一律判为非法
```

**→ 整个备份失败 → 用户永远存不上云端。**

### 修复
```js
var KEY_CHARSET = /^[A-Za-z0-9_:\-.\u4e00-\u9fff\u3040-\u30ff\uac00-\ud7af]+$/;
```

**修的是校验规则而不是排除那个键** —— 因为它是**真实的玩家学习数据**，
必须能备份、能跨设备同步。

同时保留对真正非法字符（空格、引号）的拦截，不是无脑放行。

### 教训

> **先扫真实数据，再下结论。**
> 我又一次凭"最近改了什么"去推断原因，而不是先看现场有什么。

# 第三部分 · 逐版失败记录

## 3.1 早期：完全看不见（v1017 → v1058，约 40 版）

**共同特征**：每一版都改对了一个真 bug，**但都不是真凶**。

因为 `[object Object]` 遮住了所有错误原文，只能靠推理猜。

代表性的几个：

| 版本 | 修了什么 | 为什么没解决 |
|---|---|---|
| v1028 | 云存档总是另开匿名实例 → 跨设备读不到 | 真 bug，但不是本例 |
| v1031 | 未声明 `persistence:'local'` → 刷新即掉登录 | 真 bug，但不是本例 |
| v1039 | `syncNow` 因"指纹未变"跳过写入 → 显示成功却一字未写 | 真 bug，查了十几版 |
| v1046 | 存档地址算法三处各写一份，走散 | 真 bug |
| v1047 | 账号标识用 uid（跨设备会变）→ 改用手机号 | 真 bug |
| v1054 | 门槛面板 z-index 盖住登录面板 → 点了没反应 | 真 bug |
| v1057 | `import` 了不存在的 SDK 文件名 → **手机注册从 v1004 起一直是坏的** | 真 bug |

**v1057 那个尤其典型**：动态 `import` 的 404 在微信内置浏览器**不走 `.catch`**，
于是整个 SDK 加载失败，用户点「获取验证码」只看到"连不上服务器"。
**而这只是一个写错的文件名。**

## 3.2 中期：四次猜测，四次被推翻（v1076 → v1080）

### v1076 —— 猜「匿名登录冲掉凭证」

**当时的依据**：
账号会话与匿名会话共用同一个凭证槽位；
而云存档有条"匿名兜底"路径**无条件**调 `signInAnonymously()`，
完全不看有没有账号登录。

**改了什么**：已登录时不发起匿名登录。

**被什么推翻**：用户回复「**匿名登录是开着的**」。
如果匿名登录本身没问题，那"匿名失败冲掉凭证"这条链就不成立。

**事后看**：方向是对的（多实例确实是真凶），
**但防线放错了位置** —— 我把判断写在了 `cloudbase.init()` **之后**，
实例照样被创建（实测：init 在第 12128 字符，判断在 13028，**晚了 900 字符**）。
这个位置错误直到 **v1088** 才修对。

---

### v1077 —— 猜「凭证异步还没落定」

**当时的依据**：
v1059 那行返回值自相矛盾：
```js
return { ok:false, expired:true, definite:false, reason:'云端会话已失效或尚未就绪' };
//                 ↑"确凿过期"     ↑又说"说不准"
```
而下游**只看 `expired`**，于是把「SDK 还没落定」讲成「登录已过期」。
用户按提示重新登录 → 又成功 → 又被告知过期 → **死循环**。

**改了什么**：
- 空登录态加重试 `[120, 260, 500, 900]ms`
- 区分三态：拿到 uid → ok；一直空 → `notReady`（稍候再试）；确凿鉴权错误 → `expired`（重新登录）

**被什么推翻**：
用户的轨迹图显示 **登录 62 秒后 `getLoginState()` 仍连续 5 次返回 null**。
62 秒足够任何异步操作完成 —— **不是"没落定"，是凭证根本不在。**

**事后看**：这个改进本身是对的（面板不再误导人反复重登），但不是根因。

---

### v1079 —— 猜「`getLoginState` 用错了 API」

**当时的依据**：读 SDK 源码发现：
```js
getLoginState = function(){ return this.config.credentialsClient.getCredentialsAsync() }
```
返回的是**凭证对象**（`access_token` 那套），**里面没有 uid**。
而我们的代码在找 `st.uid` —— 那不就永远取不到？

**被什么推翻**：**我自己推翻的。**
继续读源码发现 SDK 里有**两个同名的 `getLoginState`**：
- 位置 193922：内层 `authApi` 的，返回凭证对象（没有 uid）
- 位置 266146：**外层 Auth 的（我们用的这个）**，包一层 → 返回带 `.user` 的对象

**我们用的是对的那个。**

**这次值得记一笔**：假设提出后我没有立刻改代码，
而是先去验证 —— **验证救了我一次**。

---

### v1080 —— 猜「响应缺 `expires_in`」

**当时的依据**：读 SDK 源码发现：
```js
setCredentials(t) {
  if (t?.expires_in) { 存起来 }
  else { storage.removeItem(...); credentials = null }   // ← 直接删！
}
```
而 `signUp` / `signIn` 把服务端返回值**原样**丢给 `setCredentials`。
只要那次响应缺 `expires_in`，凭证就被整个删掉，**而 Promise 依然 resolve**。

**改了什么**：登录后必须确认 `credentials_<env>` 键真的存在，否则不写"已登录"。

**结果**：有源码依据，改动本身也是对的（"没报错 ≠ 成功"），
**但不是本例成因** —— 后来的生死簿证明凭证是**写进去了又被删**，不是没写进去。

### 🔴 v1086/v1087 —— 工具本身也漏了

用户截图显示：
```

```
而 `credentials_*` 确实不在，本地登录记录却显示**登录发生在 49 秒前**。

**唯一解释：登录与凭证消失都发生在这个页面加载之前。**

> **那句「没有记录」不是答案，是我的工具漏了。**
> 这正是"看起来在工作、其实没在看" —— **诊断工具犯这个错代价最大**，
> 因为它会让人把「没记录」误当成「没人动过」。

**v1087 修法**：
1. 日志写进 localStorage，**跨重载累积**，并标出每次「── 页面加载 ──」分界线
2. 登录时刻也写进同一条时间线
3. 网络记录同样持久化
4. **劫持装不上时必须明说**，而不是给出误导性的"没有记录"

**修完立刻见效** —— v1088 就靠它抓到了 `invalid_grant | already refreshed`。

## 4.2 最值得记住的三条

### ① 诊断工具本身出错，代价最大

普通代码出错，用户看到"功能坏了"；
**诊断工具出错，所有人（包括开发者）都被误导到错误的方向。**

v1086 那句"没有任何模块动过凭证"，差点让我彻底放弃"凭证被删"这条线。

### ② "没报错"不等于"成功"

登录链路原本是：
```js
}).then(function () {              // ← 完全不看返回了什么
  writeLocal({ method:'phone', signedAt: Date.now() });
```
只要 Promise 没 reject 就标记成功 —— **这就是「界面说已登录、云端其实没会话」的源头。**

> **凡是"对方说成功"的地方，都要问一句：有没有留下可验证的痕迹？**

### ③ 属性正确 ≠ 用户用得了

我测过：实例数=1 ✅、34 页零错误 ✅、体检 86 分 ✅
**然后用户连登录都点不了。**

> **发布前必须走一遍"用户真实点击流程"，而不是只测自己改的函数返回什么。**

# 第五部分 · 沉淀下来的工具与制度

## 5.1 诊断面板（用户端，最有价值的产出）

| 区块 | 作用 |
|---|---|
| **⓪ 当前版本** | `模块 vXXXX · 页面 vXXXX`，不一致 = 缓存卡住 |
| **🔄 强制更新** | 注销 SW + 清缓存 + 硬重载 |
| **🪤 凭证生死簿** | **谁在什么时候动了凭证 + 调用栈 + 失败的云端请求**，跨重载存活 |
| **🔬 会话探测轨迹** | 探测了几次、每次拿到什么、最终结论 |

**下次云端出问题，让用户截「🪤 凭证生死簿」那一块** —— 它会直接写出凶手。

## 5.2 版本守望者（`hansen_version_watch_v1083.js`）

彻底解决「做出来的东西不显示」：

```
开机空闲时 → no-store 取 /VERSION（绕开一切缓存）
服务器更新了 → 自动注销 SW + 清空缓存 + 硬重载
同一版本只自动修一次 → 绝不把人卡在重载循环里
iframe 内只委托顶层 → 在子框重载等于白修
XHR 兜底 → 老内核没 fetch 也能工作
绝对路径 → iframe/子路径下不会取错地址
```

## 5.3 凭证守护（`hansen_cred_guard_v1092.js`）

SDK 内部改不了，在外面兜住：
1. **持续备份**影子副本（带时间戳）
2. **失败即救回** —— 凭证被删且本地仍记着已登录 → 写回去
3. **跨页面刷新锁** —— 同一时刻只允许一个页面刷新

极其克制：只在本地明确已登录时才救 / 影子超 12h 不用 /
救援封顶 3 次防死循环 / 锁带 8 秒超时。

## 5.4 贾维斯（质量守卫体系）

**23 道守卫 · 49 条事故登记 · 四档发版闸门 · 100 分制评分**

```
一档    23 道守卫必须全绿
一档半  事故登记册：每个 🔴 修复都要有真实看守者
一档⅔   守卫自证：每道守卫注入故障样本必须变红
二档    既有问题数不许比基线多（基线只降不升）
       ↓ 全过才签发凭证
package_release 见不到有效凭证 → 拒绝出包
```

**关键设计**：
- 「每版必跑」在 v1059~v1069 **连丢十一版**（全靠人记得）→ v1070 变成发版硬条件
- 守卫自己也会失灵 → v1074 加「守卫自证」（注入故障样本，变不红 = 已失灵）
- 贾维斯自己会落后 → v1074 加落后检测（登记册/知识库落后就报红）

**这套体系在收尾阶段拦下我三次**：新模块无人看守、事故漏登、知识库落后。

# 附：这个问题为什么客观上确实难

**它不是一个 bug，是六个独立的 bug 叠在一起**：

```
① 登录状态两个真源           （逻辑错误）
② [object Object] 遮住错误   （可观测性缺失）
③ 文案被老规则改写           （可观测性缺失）
④ SW 缓存住旧代码            （部署链路问题）
⑤ 多实例并发刷新 token       （SDK 行为 + 架构问题）
⑥ 备份不认中文键名           （字符集问题）
```

**每修掉一个，下一个才浮出水面。** 而其中 ②③④ 三个都属于
"让人看不见真相"的那一类 —— 它们不直接导致失败，
**但会让每一次诊断都建立在错误的信息上。**

**如果一开始就先解决②③④（可观测性），后面三个真凶大概三五版就能定位。**

> 这就是这份笔记最核心的一句话：
> **先修"看得见"，再修"修得好"。**
