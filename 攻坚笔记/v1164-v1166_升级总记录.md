## 0. 一句话

v1163 的天梯和房间对战**从设计上就不可能在真机上跑通**（客人要改房主建的记录，而数据库只许创建者改；报错又被悄悄吞掉）。
这一轮把联机的地基**推倒重做**，同时对整个小程序做了八个方面的检查、教学内容校对、隐私审查、产品优化审查和主题画面审查，
并开了多台云端机器并行做主题 2.0、复习系统 2.0、自动质量关卡和对战界面重新设计。

## 1. 起因（老师在真机上看到的）

- 点「天梯排位」→「连不上网络 / 检查一下 Wi-Fi 或数据再试」，而网络是好的；点了也不直接进匹配界面。
- 反复报「建房不行」「天梯匹配不到」。v1157–v1163 修过 22 个对战相关 bug，问题一直在。

## 2. 怎么查的

- 这台云端工作机**连不上腾讯云**（代理拒绝），真服务器的行为只能推断，所以：
  1. **读 SDK 源码**：`vendor_cloudbase_esm_v965.js` 实际是 `@cloudbase/js-sdk 2.30.0`，逐段按偏移量阅读（偏移量都写在取证记录里）。
  2. **真 SDK + 本地模拟腾讯云**：浏览器里跑真 SDK 和真页面，只把发往腾讯的网络请求交给本地「模拟云端」回答（权限、延迟、数据晚到、报错都能模拟）。
  3. **每条结论都安排人专门反驳**：一人查、一人复现或推翻，推翻不了才算数。
- 取证全文：[`v1164/取证与反驳_forensics.txt`](v1164/取证与反驳_forensics.txt)。

## 3. 查到的根因（v1163）

| # | 问题 | 后果 |
|---|---|---|
| 1 | 客人进房、心跳、准备、抢答、交卷、离开、判对方掉线，**全都要改房主建的那条房间记录**；而 `hansen_pk_rooms` 的权限是「读取全部数据，修改本人数据」（只有创建者能改） | 客人每一步都悄悄失败：界面只说「这间房刚被别人抢走了」并无限循环；房主干等两分钟 |
| 2 | SDK 遇到数据库报错（权限拒绝、缺表等）**不抛出，而是当成正常结果返回**；app 从不检查 `code` | 权限错看起来像「没有房间」「被抢走了」「成功了」，任何测试和界面都看不见真正原因 |
| 3 | 「连不上网络」其实来自：任何非 200 的回应、超时、登录凭证刷新失败等，都被 SDK 统一成 `network request error`，app 又没认出这句 | 网是好的也显示「连不上网络」 |
| 4 | 登录状态里的用户 ID **只从手机本地一份缓存读**；`getLoginState()` 出任何错都只返回空，app 把一切失败都说成「尚未就绪」 | 已登录的孩子可能永远「云端会话尚未就绪」；凭证真没了也不提示重新登录 |
| 5 | **「用户名 + 密码注册」从来没在云端建出账号**（SDK 的 `signUp({email})` 只发一封验证码邮件），app 却写下「已登录」 | 用这种方式注册的孩子，天梯、房间、云存档全都用不了 |
| 6 | 备份把 SDK 自己的数据（`user_info_<env>`、`device_id` 等）也当成玩家数据导出和恢复 | 可能抹掉或换掉登录缓存 |
| 7 | 岛屿里的天梯和好友界面层级比「拼写大PK」低 | 岛里点天梯「好像没反应」，界面被压在下面 |
| 8 | 两人几乎同时点「开始排位」→ 各自开一间房、互相永远看不到 | 卡死两分钟 |
| 9 | 关掉天梯会误弹「这一步没能打开」救援框，救援框的按钮又会再次触发它 | 死循环 |
| 10 | 等满两分钟没人来：不关房、不停心跳 | 留下「幽灵房」，别人进去对着空房 |
| 11 | 房主先结束会立刻删房 | 客人的成绩丢失 |
| 12 | 房间记录里明文存着**玩家手机号**，所有登录的人都读得到 | 隐私泄露 |
| 13 | 名字永远显示「无名蜂」、房主不知道客人的天梯分 | 加减分算错 |

## 4. v1164 的重做：设计与取舍

**原则：每个玩家只写自己建的记录。**

- 房间（房主建）、座位（客人建，编号 = 房间号 + `_s` + 座位轮次）、每回合结果（谁抢到谁建，编号 = 房间号 + `_w` + 回合号）。
- 「抢座位」「抢答」靠**用同一个编号新建记录，只有第一个能建成**（数据库保证编号唯一），建完一定**回读确认**（不依赖服务器报错长什么样）。
- 房主看到座位后写确认，**还要等客人回话**才开打；客人掉线或取消，房主撤回确认、换下一个座位轮次。
- 回合赛 / 同步赛：两个人都答完（或超时）才进下一个词。
- 判断对方掉线：只看「对方心跳的值多久没变过」，用**本机时钟**计时，不受两台手机时间差影响。
- 所有云端调用检查 `code`；错误分成：断网 / 太慢 / 会话没准备好 / 登录过期 / 云端设置不对 / 房已没了 / 被抢走 / 自己账号的房 / 其他，界面按种类说真实原因，「技术信息」保留原话。
- 身份用 `u + 云端用户 ID`，**房间记录里不再出现手机号或用户名**；名字从玩家资料取。
- 新版记录带 `proto: 2`，旧版本留下的房间一律不显示。
- **不需要老师改任何控制台设置**。

**考虑过、没采用的方案：**

| 方案 | 为什么没用 |
|---|---|
| 让老师把房间表改成「自定义安全规则：登录的人都能写」 | 要老师在后台操作，这里没法验证改得对不对；而且任何人都能改、删别人的房 |
| 用云函数做裁判 | 要老师部署云函数，同样没法在这里验证 |
| 继续用「条件更新」抢房 | 在现有权限下客人根本改不了房主的记录；文档还说基础权限下客户端批量更新可能直接被拒 |

设计全文：[`v1164/设计规格_SPEC_v1164.md`](v1164/设计规格_SPEC_v1164.md)。

- **安全（最严重）**：好友页存在存储型 XSS，可读走孩子的手机号和登录凭证（SEC-1）。

- **云端额度**：对战和匹配每台手机约每秒 3 次读、好友在线心跳在 3 个页面框里同时跑，一个班一起玩会用光个人版额度（SE-1、SE-2）。
- **公平与健壮**：陌生人能预先建「回合结果」替别人决定输赢（F9）、伪造房间淹没列表（F10）、两台手机时间差影响倒计时和房间可见（F7、F8）、两人同时断网都判自己赢（F4）、数据延迟很大时刚建的房被自己判没了（F6）等。
- 审查方法：每个方向一人查、一人复现，确认后统一修，修完只复查改过的地方，直到一轮挑不出新问题。
- 另有独立的「随机模拟上万局」压力测试（`v1164-v1166_工具与记录/scratchpad/soak/`）：多台虚拟手机随机进房、退出、断网、抢答，网络随机变慢/丢包，时钟故意调错，外加一个作弊者；每局检查 10 条规则（只一人抢到座位、两边比分一致、没人改别人的记录、每局能结束、作弊无效……）。
